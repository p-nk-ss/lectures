# Банк тестових питань: клінічне мислення замість зазубрювання

## Context

Тести на сайті відчуваються повторюваними і перевіряють не те, що треба. Дві окремі причини:

1. **Немає рандомізації.** `Quiz.tsx:25` робить `const [pool] = useState(questions)` — прогон завжди бере всі 20 питань одного файлу в тому самому порядку, з відповідями на тих самих позиціях. Навіть без нового контенту це головна причина відчуття «одне й те саме».
2. **Питання recall-типу.** 320 питань (16 файлів × 20), середня довжина тексту питання 70 символів, віньєток — **8 на 320**. Це «яка доза», «коли вводять», а не «пацієнт такий-то, що робите».

Про «немає БД»: вона й не потрібна. Зараз усі quiz JSON — 300 KB, `dist` — 5.7 MB. Банк утричі більший = +600 KB статики. Єдина реальна вага — питання інлайняться у props острівця (сторінка тесту 32 KB HTML); це вирішується підвантаженням банку окремим JSON.

Рішення автора: банк **60 питань на тест**, прогон **20 випадкових**; короткі віньєтки (2–4 речення, одне питання); ~60 % кейсів у банку; зарубіжні кейси як каркас, переписані українською з адаптацією препаратів; старі 320 прополоти, не переписувати; таймер 15 хв; пам'ятати останні 2 прогони, щоб не повторювати.

**Властивість, що дозволяє випускати поетапно:** вибірка обмежується наявним банком, тому рушій працює і на банку з 20. Спершу рушій (одразу лікує повтори), далі — теми по одній.

## Частина 1 — Рушій вибірки (окремий, самодостатній етап)

### 1.1 Схема контенту

`site/src/content.config.ts`, об'єкт `question` — два нові поля:

```ts
kind: z.enum(['case', 'recall']).default('recall'),
source: z.string().optional(),   // гайдлайн + походження кейсу; у UI не рендериться
```

`source` навмисно не показується: висота екрана прогону — дефіцитний ресурс (див. «Quiz layout» у CLAUDE.md). Він живе поруч із твердженням, щоб не розходитися з ним, і читається під час ревʼю.

Файли банку розділяються на два на рівень — це одиниця авторської роботи й ревʼю:

- `NN-nurse.json` / `NN-doctor.json` — існуючі, прополоті;
- `NN-nurse-cases.json` / `NN-doctor-cases.json` — нові віньєтки.

Обидва оголошують ті самі `topic` + `level`. `kind` живе на питанні (джерело правди для квоти), поділ файлів — суто для зручності редагування.

### 1.2 Зʼєднання файлів

- `src/pages/tests/[topic]/[level].astro` — `getStaticPaths` зараз мапить 1 запис → 1 маршрут; згрупувати за `topic+level` і злити `questions`.
- `src/pages/tests/index.astro` — той самий grouping; на картці писати «20 питань з банку 60», а не `questions.length`.

### 1.3 Чисті функції вибірки — `src/lib/quiz.ts`

```ts
export const QUIZ_RUN_SIZE = 20;
export const CASE_SHARE = 0.6;      // 12 кейсів із 20
export const SEEN_RUNS = 2;         // скільки прогонів пам'ятаємо
export const QUIZ_TIME_LIMIT = 15 * 60;   // було 10 * 60

export function pickRun(bank: Question[], seen: string[], rnd = Math.random): Question[]
export function shuffleOptions(q: Question, rnd = Math.random): Question
```

`pickRun`:
1. поділити банк на `case` / `recall`;
2. цілі: `round(20 * 0.6)` = 12 кейсів, 8 recall; кожну ціль обрізати наявним і добрати нестачу з іншого пулу — банк із 20 має віддавати 20;
3. усередині пулу спершу невидані (`!seen.includes(id)`), перемішані; якщо невиданих мало — добрати з виданих;
4. перемішати підсумкові 20.

`shuffleOptions` переставляє `options` і перераховує індекси `correct`. Безпечно: перевірив — жодне пояснення не посилається на порядок варіантів, позиційних пасток «усі перелічені» немає.

`rnd` інʼєктується, щоб тести були детерміновані — той самий підхід, що вже вживається для `store: Storage = localStorage` у `storage.ts`.

### 1.4 Памʼять виданих — `src/lib/storage.ts`

```ts
export const seenKey = (topic, level) => `${KEY_PREFIX}seen:${topic}:${level}`;
export function getSeen(topic, level, store?): string[]
export function pushSeen(topic, level, ids, store?): void   // обрізає до QUIZ_RUN_SIZE * SEEN_RUNS
```

**Не забути:** `clearAllQuizzes` і `clearTopicQuizzes` фільтрують за префіксом `aiti:quiz:` — новий `aiti:seen:` треба додати в обидва, інакше «скинути тести» залишить памʼять. `clearEverything` бере все за `KEY_PREFIX` і працює як є. Оновити `storage.test.ts` (лічильники видалених ключів у наявних тестах зміняться).

### 1.5 Підвантаження банку замість інлайну

Новий ендпоїнт `src/pages/tests/[topic]/[level]/bank.json.ts` (`getStaticPaths` як у сторінки, `GET` віддає злитий банк). Якщо Astro не дасть співіснувати `[level].astro` і теці `[level]/` — запасний варіант `src/pages/tests/[topic]/[level]-bank.json.ts`.

`Quiz.tsx`: `questions` більше не проп. Fetch стартує в `useEffect` на монтуванні (читач у цей час читає панель правил), кнопка «ПОЧАТИ» неактивна до завантаження. Помилка мережі — повідомлення + «спробувати ще раз». Прогон збирається в момент старту: `pickRun(bank, getSeen(...)).map(q => shuffleOptions(q))`, далі `pushSeen(...)`.

`restart()` перезбирає прогон (нові 20), `retryWrong()` лишається практикою на тих самих питаннях.

### 1.6 Правила довжини для нового контенту

Виміряні поточні максимуми, за якими вже перевірена вʼорстка: `vignette + text` ≤ 315, пояснення ≤ 329, варіант p95 = 84. Ліміти для нового контенту:

- `vignette` + `text` ≤ **320 символів**;
- `explanation` ≤ **330**;
- кожен варіант ≤ **120**;
- 4 варіанти (усі 320 наявних питань мають 4; схема дозволяє 5, але не змішувати).

Швидкість друку правити не треба: `MAX_LINE_MS = 3500` у `typewriter.ts` уже стискає довгу віньєтку.

## Частина 2 — Контент, тема за темою

Одиниця роботи = одна тема (обидва рівні). 8 таких одиниць, кожна випускається окремо.

### 2.1 Прополка наявних 20 на рівень

Викинути чисте зазубрювання (роки, номери наказів, питання про назву класифікації); частину переформулювати в клінічну; решту лишити з `kind: 'recall'` і проставленим `source`. Питань із цифрами в тексті й без віньєтки — 25 на 320; це не все, що треба чистити, але добрий стартовий список.

### 2.2 Написати ~40 нових на рівень (≈36 кейсів + ≈4 recall)

Пошук у мережі: LITFL, EMCases, ALiEM, WikEM, StatPearls, кейс-репорти PMC, навчальні сценарії ERC/AHA. Кейс береться як клінічна канва, **текст переписується українською** — не переклад.

Адаптація під Україну (обовʼязково перевіряти, а не памʼятати):
- препарат має бути в Держреєстрі лікарських засобів; якщо кейс тримається на недоступному препараті — або перебудувати кейс, або зробити саме недоступність предметом питання;
- одиниці: ммоль/л, °C, мм рт. ст. (не mg/dL);
- запис шляхів `в/в`, `в/к` за правилом CLAUDE.md;
- терміни, які потребують пояснення, — у глосарій, як і в лекціях.

Кожне питання отримує `source`: гайдлайн для клінічного твердження + звідки взято канву кейсу.

### 2.3 Ревʼю

У `docs/reviews/<slug>.md` — новий розділ «Тестові питання»: політика джерел для цієї теми, таблиця тільки для питань із числовим/протокольним твердженням, перелік походження кейсів, і окремо — що винесено на рішення автора. Повна таблиця на 120 рядків на тему не потрібна: `source` у JSON стоїть поруч із твердженням і не роз'їжджається з ним.

## Verification

**Рушій:**
- `npx vitest run src/lib/quiz.test.ts src/lib/storage.test.ts` — `pickRun` із фіксованим `rnd`: тримає квоту 12/8; на банку з 20 віддає 20; віддає перевагу невиданим; банк, менший за квоту кейсів, добирає recall; фікстура з 1 питанням не падає. `shuffleOptions`: `isCorrect` дає той самий вердикт до і після перестановки. `pushSeen` обрізає до 40; `clearAllQuizzes` прибирає і `aiti:seen:`.
- `npm test` — уся сюїта.
- `npm run check` — 0 помилок.

**Наскрізно** (`npm run build && npm run preview`):
- `/tests/03/doctor/bank.json` віддає 200 і містить обидва файли теми;
- HTML сторінки тесту помітно легший за поточні 32 KB;
- два прогони поспіль дають різні набори питань і різний порядок варіантів;
- скидання тестів у ⚙ прибирає і памʼять виданих (перевірити ключі `aiti:` у DevTools);
- Playwright на 1024×600: найдовша віньєтка + найдовше пояснення вміщаються без скролу (це умова, зафіксована в CLAUDE.md).

**Контент теми:** `npm run build` (схема впаде на порушенні `kind`/`source`/довжин), плюс прохід очима по прогону обох рівнів теми.
